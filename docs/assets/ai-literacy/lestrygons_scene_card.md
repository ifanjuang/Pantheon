# Lestrygons — déceler la fausse enceinte

Status: support documentaire, non canonique, non executable.

Portee : fiche detaillee pour les diptyques pedagogiques Ulysse / Hercule.

Cette fiche complete `ulysse_ai_traps.md` et devra etre integree a `ulysse_scene_cards.md` lors d'une passe de reconciliation globale.

Elle ne definit aucun runtime, aucun agent, aucun outil, aucun workflow executable et aucune memoire canonique.

Doctrine Pantheon preservee :

```text
OpenWebUI expose.
Hermes Agent execute.
Pantheon Next gouverne.
```


## 1. Le recit mythologique

Apres l'episode d'Eole, Ulysse et ses compagnons arrivent au pays des Lestrygons.

Ils entrent dans un port remarquable : une rade etroite, encaissee, entouree de hautes falaises.

L'endroit semble protege.

Les navires peuvent y entrer, mais l'ouverture vers la mer est resserree.

C'est un espace qui donne une impression d'abri.

Presque toute la flotte s'engage dans ce port.

Ulysse, plus prudent, garde son propre navire a l'exterieur, pres de l'entree.

Des eclaireurs sont envoyes vers la cite.

Ils rencontrent une jeune fille, puis la reine, puis le roi Antiphates.

Mais l'accueil tourne au cauchemar.

Les Lestrygons sont des geants anthropophages.

Ils attaquent les compagnons, lancent des rochers depuis les hauteurs, ecrasent les navires enfermes dans le port et massacrent presque toute la flotte.

Le piege est spatial.

Ce qui ressemblait a un abri devient une nasse.

Le port n'etait pas une protection.

C'etait un espace de capture.

## 2. Les themes profonds

Le theme central est la fausse cloture.

Les marins croient entrer dans un espace protege.

En realite, ils entrent dans un dispositif ou la sortie est difficile et ou les hauteurs appartiennent a l'ennemi.

Philosophiquement, les Lestrygons posent la question de la difference entre enceinte et protection.

Tout ce qui entoure ne protege pas.

Une limite peut rassurer visuellement tout en rendant vulnerable.

Psychologiquement, l'episode parle de l'effet de securite produit par la forme.

Un port ferme, une interface nette, un espace silencieux, un environnement controle : tout cela peut produire une impression de maitrise.

Mais l'impression de cloture n'est pas la preuve d'une securite reelle.

Sociologiquement, les Lestrygons rappellent qu'un systeme n'est jamais seulement ce que l'utilisateur voit.

Il y a l'espace visible, puis les hauteurs invisibles : infrastructures, intermediaires, operateurs, traitements, acces, regles, dependances.

Epistemologiquement, l'episode montre que le statut d'un espace ne se deduit pas de son apparence.

Il faut comprendre ses flux, ses sorties, ses dependances, ses seuils, ses acteurs et ses points de transfert.

## 3. Transposition IA

Avec l'IA, les Lestrygons parlent de la porosite des plateformes.

L'utilisateur voit une interface propre : une fenetre de chat, un bouton d'upload, une zone de fichiers, une base documentaire, un connecteur, un agent, un outil.

Tout semble localise dans cet espace.

Mais une plateforme IA n'est pas seulement une fenetre.

C'est un systeme :

```text
interface
logs
fichiers
memoire eventuelle
bases documentaires
connecteurs
outils
appels externes
API
sous-traitants
parametres de confidentialite
regles de conservation
droits d'acces
```

Le piege n'est pas de dire que toute plateforme serait dangereuse.

Ce serait trop grossier.

Le piege est de croire que l'interface visible garantit a elle seule l'etancheite du systeme.

```text
Ce qui parait enferme dans l'interface
peut circuler dans le systeme.
```

## 4. Le piege

Le piege des Lestrygons est de confondre espace ferme et systeme maitrise.

On depose un fichier.

On colle un contrat.

On branche un connecteur.

On active un outil.

On interroge une base documentaire.

On demande a un agent d'aller chercher, comparer, resumer, classer.

Visuellement, tout se passe dans la meme interface.

Mais techniquement et organisationnellement, les fragments peuvent circuler ailleurs si le cadre est mal pose :

```text
requetes externes
outils tiers
logs
indexation
historique
memoire
stockage
connecteurs
droits d'acces
exports
appels API
traitements par sous-traitants
```

Le port semble ferme.

Mais les hauteurs dominent la flotte.

Autrement dit :

```text
L'interface rassure.
L'architecture decide.
```

## 5. Exemple concret

Un architecte charge dans une plateforme IA :

```text
devis
plans
photos de chantier
rapport d'expertise
mails client
pieces administratives
documents de copropriete
elements financiers
```

L'interface donne l'impression d'un espace unique et maitrise.

Mais la vraie question est :

```text
Ou vont les fichiers ?
Sont-ils indexes ?
Sont-ils conserves ?
Sont-ils utilises pour entrainer un modele ?
Quels outils externes peuvent etre appeles ?
Quels connecteurs sont actifs ?
Quels logs sont produits ?
Qui peut acceder a l'espace ?
Quel projet est isole de quel autre ?
Quelles donnees sensibles doivent etre anonymisees ?
```

Sans ces reponses, on ne sait pas si l'espace est un atelier, un port sur ou une nasse.

Autre exemple : un agent IA connecte a un outil web, a un drive, a un CRM ou a une messagerie.

L'utilisateur croit dialoguer dans une fenetre unique.

En realite, l'agent peut declencher des appels, transmettre des fragments, recuperer des donnees, ouvrir des connexions.

Ce n'est pas forcement mauvais.

Mais ce n'est pas neutre.

## 6. Garde-fou

Le garde-fou des Lestrygons consiste a examiner l'architecture du systeme avant de croire l'interface.

Avant d'utiliser une plateforme IA avec des donnees sensibles, verifier :

```text
perimetre du projet
parametres de confidentialite
politique de conservation
usage ou non pour entrainement
lieu de stockage
droits d'acces
connecteurs actifs
outils externes disponibles
logs produits
memoire activee ou non
isolation entre projets
possibilite de suppression
niveau d'anonymisation requis
```

Dans une logique Pantheon :

```text
interface != enceinte
upload != securite
chat != isolation
connecteur != neutralite
outil externe != espace ferme
```

Le bon reflexe n'est pas la paranoia.

C'est la qualification du perimetre.

# Cerbere — garder les seuils du retour

Status: support documentaire, non canonique, non executable.

Portee : fiche detaillee pour les diptyques pedagogiques Ulysse / Hercule.

Cette fiche complete `hercule_ai_discipline.md` et devra etre integree a une future version longue reconciliee du corpus Hercule.

Elle ne definit aucun runtime, aucun agent, aucun outil, aucun workflow executable et aucune memoire canonique.

Doctrine Pantheon preservee :

```text
OpenWebUI expose.
Hermes Agent execute.
Pantheon Next gouverne.
```

## Repartition avec les epreuves voisines

Cette fiche distingue les deux derniers seuils :

```text
Pommes  = murir le livrable sous responsabilite.
Cerbere = garder les seuils du retour.
```

Les Pommes demandent : quelle sortie peut devenir livrable assumable ?

Cerbere demande : qu'est-ce qui reste, qu'est-ce qui passe, qu'est-ce qui revient, qu'est-ce qui doit disparaitre ?

Les Pommes traitent la charge du fruit cueilli.

Cerbere traite la duree de ce qui reste apres la cueillette.

## 1. Le recit mythologique

Cerbere est le chien d'Hades.

Il garde l'entree des Enfers.

Il n'est pas un monstre errant.

Il est un gardien de seuil.

Sa fonction n'est pas seulement d'empecher les vivants d'entrer.

Il empeche surtout que les morts ressortent et que la frontiere entre les mondes soit franchie n'importe comment.

Le dernier travail d'Hercule consiste a descendre aux Enfers et a ramener Cerbere a Eurysthee.

Dans plusieurs versions, Hercule ne vole pas Cerbere.

Il obtient une autorisation d'Hades, sous condition : maitriser Cerbere sans armes.

Ce detail est essentiel.

Le dernier travail exige une maitrise nue, precise, sans violence instrumentale excessive.

Hercule descend donc dans un monde de seuils, de rites, de guides et de conditions.

Il maitrise Cerbere, le ramene a la surface, le montre, puis Cerbere retourne aux Enfers.

Hercule ne garde pas Cerbere comme trophee.

Le gardien retourne a sa juste place.

Le mythe ne celebre donc pas la possession du seuil.

Il montre qu'on peut franchir, exposer et comprendre un seuil, mais qu'il faut ensuite remettre chaque chose dans son lieu legitime.

## 2. Les themes profonds

Cerbere ne garde pas un tresor.

Il garde un seuil.

Il garde la difference entre :

```text
ce qui passe
ce qui reste
ce qui revient
ce qui doit demeurer en retrait
```

Avec l'IA, ce seuil concerne la duree des traces.

Apres le travail, il reste :

```text
prompts
sources
brouillons
versions
hypotheses
patchs candidats
sorties candidates
preuves
logs
decisions preparees
fichiers
memoires candidates
memoires canoniques
archives
donnees sensibles
```

La question finale n'est donc pas seulement :

```text
Qu'avons-nous produit ?
```

Elle devient :

```text
Qu'est-ce qui reste ?
Qu'est-ce qui disparait ?
Qu'est-ce qui devient memoire ?
Qu'est-ce qui engage ?
Qu'est-ce qui peut revenir plus tard ?
Qu'est-ce qui ne doit surtout pas revenir comme verite ?
```

## 3. Garder n'est pas accumuler

Le piege de Cerbere est l'accumulation.

Tout garder semble prudent.

Mais tout garder cree une memoire sale, lourde et dangereuse.

A l'inverse, tout effacer peut detruire la preuve, la continuite, la responsabilite et la capacite d'audit.

Cerbere ne dit donc pas :

```text
garder toute la memoire
```

Il dit :

```text
garder le seuil
```

```text
Garder n'est pas accumuler.
C'est decider ce qui a le droit de revenir.
```

Cette phrase est la doctrine de l'epreuve.

La memoire IA n'est pas un stockage neutre.

Ce qui est garde peut revenir dans un raisonnement futur, orienter une reponse, influencer un dossier ou faire autorite.

Il faut donc gouverner le retour.

## 4. Le retour mal garde

Cerbere garde le retour.

Dans un systeme IA, une trace mal qualifiee peut revenir avec le mauvais statut.

Exemples :

```text
une hypothese revient comme fait etabli
un brouillon revient comme decision
une source obsolete revient comme reference
une erreur corrigee continue d'orienter le systeme
une memoire candidate agit comme memoire canonique
une information sensible revient hors perimetre
une preference ponctuelle devient regle generale
une sortie candidate revient comme livrable valide
```

Le risque n'est donc pas seulement de conserver trop.

Le risque est de laisser revenir ce qui n'avait pas le droit de revenir ainsi.

```text
Une memoire mal gardee
fait revenir
ce qui aurait du rester mort.
```

Cette phrase est volontairement sombre.

Elle rend visible le danger propre a Cerbere : le retour non gouverne.

## 5. Les trois tetes de Cerbere

Les trois tetes de Cerbere peuvent structurer la discipline.

### Donnee

```text
Cette information peut-elle rester ?
Est-elle sensible ?
Est-elle personnelle ?
Est-elle encore utile ?
A-t-elle une duree d'usage ?
Doit-elle etre retiree ?
```

### Decision

```text
Cette sortie engage-t-elle quelqu'un ?
Est-ce un brouillon ?
Une hypothese ?
Une version candidate ?
Une decision preparee ?
Un livrable valide ?
Un engagement signe ?
```

### Memoire

```text
Cette trace a-t-elle le droit de revenir ?
Doit-elle rester ephemere ?
Devenir archive ?
Devenir memoire candidate ?
Devenir memoire canonique ?
Ou etre supprimee ?
```

Cerbere garde donc trois seuils :

```text
donnee
decision
memoire
```

Ou, plus abstraitement :

```text
trace
engagement
retour
```

## 6. Usage ponctuel et droit de demeure

L'un des points les plus importants est la difference entre usage et demeure.

Une information peut etre utile pendant une tache sans devoir rester durablement.

Un contexte peut aider une analyse sans devenir memoire.

Une hypothese peut guider une recherche sans devenir preuve.

Un brouillon peut servir sans devenir archive principale.

Une donnee sensible peut etre traitee puis retiree.

Une decision preparee peut rester candidate sans devenir decision validee.

```text
L'usage ponctuel
n'est pas un droit de demeure.
```

Cette phrase distingue Cerbere de la Ceinture.

La Ceinture gouverne la circulation.

Cerbere gouverne la demeure, la duree et le retour.

## 7. Capturer sans armes

Dans plusieurs versions, Hades autorise Hercule a prendre Cerbere a condition de le maitriser sans armes.

Cette contrainte donne une lecture importante : la gouvernance des traces ne doit pas etre brutale.

Il ne s'agit pas de tout garder ou de tout supprimer.

Il ne s'agit pas de tout verrouiller ou de tout canoniser.

Il faut classer avec precision.

```text
ephemere
brouillon
candidat
a verifier
valide
sensible
a conserver
a supprimer
memoire candidate
memoire canonique
archive
```

Le seuil ne se garde pas par accumulation.

Il se garde par statut.

```text
Le seuil ne se garde pas par accumulation.
Il se garde par statut.
```

## 8. Autorisation du seuil

Hercule descend aux Enfers, mais il ne s'arroge pas le droit de tout faire.

Il demande a Hades.

Le franchissement du seuil est autorise, borne, conditionne et reversible.

Avec l'IA, cela correspond aux questions finales :

```text
Peut-on conserver cette sortie ?
Peut-on la reutiliser ?
Peut-on la transformer en memoire ?
Peut-on l'archiver ?
Peut-on la transmettre ?
Peut-on la laisser revenir dans un futur raisonnement ?
Qui autorise ce retour ?
```

Une trace ne devient pas durable par inertie.

Elle doit recevoir un statut et, si necessaire, une autorisation.

## 9. Retour a la juste place

Hercule ramene Cerbere a Eurysthee, mais Cerbere retourne aux Enfers.

Ce motif est capital.

Tout ce qui traverse le seuil pour une tache n'a pas vocation a rester durablement dans le monde actif.

Certains elements doivent retourner a l'ombre.

```text
Ce qui a servi au passage
ne doit pas toujours demeurer.
```

Ou plus mythologique :

```text
Ce qui a franchi le seuil pour une tache
doit parfois retourner a l'ombre.
```

Cerbere rappelle donc qu'une trace utile n'est pas forcement une trace durable.

## 10. Tout ne doit pas etre sauve

Dans certaines traditions, Hercule rencontre Thesee et Pirithoos aux Enfers.

Il peut sauver l'un, mais pas toujours l'autre.

La lecon est nette : tout ne peut pas etre remonte du monde d'en bas.

Avec l'IA, tout ce qui a ete produit pendant une tache ne merite pas d'etre sauve.

Il faut parfois laisser :

```text
une idee
un brouillon
une hypothese
une piste
une reformulation
une version
une source faible
une preference temporaire
une erreur corrigee
```

La maturite finale, c'est aussi savoir ce qu'on ne remonte pas.

Cerbere prolonge donc les Pommes : les Pommes disent ce que l'on peut porter ; Cerbere dit ce que l'on ne doit pas faire revenir.

## 11. Archive et autorite

L'archive n'est pas un simple depot.

Ce qui est archive peut etre retrouve, cite, reactive, reinterprete et parfois faire autorite.

Dans une pratique IA, ce qui est garde peut devenir une contrainte invisible.

La question n'est donc pas seulement :

```text
Faut-il garder ?
```

Mais :

```text
Quel pouvoir donnera-t-on a ce qui reste ?
```

```text
Ce qui reste
prepare deja
ce qui fera autorite.
```

Une archive mal tenue peut donner de l'autorite a ce qui n'a jamais ete valide.

## 12. Cerbere dans Pantheon

Pour Pantheon, Cerbere est le gardien des statuts dans la duree.

Il protege la difference entre :

```text
source
preuve
hypothese
sortie candidate
livrable valide
trace
archive
memoire candidate
memoire canonique
```

Sans Cerbere, tout se melange apres coup.

Et quand tout se melange, le systeme reutilise des elements avec le mauvais statut.

Cerbere preserve donc une regle centrale :

```text
Le valide peut rester.
Le candidat doit rester marque.
Le sensible doit rester garde.
L'obsolete doit pouvoir mourir.
```

## 13. Difference avec Pommes

Les Pommes demandent :

```text
Ce livrable peut-il etre cueilli, porte et assume ?
```

Cerbere demande :

```text
Ce qui reste apres le livrable a-t-il le droit de revenir ?
```

Les Pommes concernent la maturite du fruit.

Cerbere concerne le seuil de la duree.

```text
Pommes : peut-on livrer ?
Cerbere : que laisse-t-on revenir ?
```

## 14. Discipline active

Apres toute production significative, classer les traces :

```text
ephemere
brouillon
hypothese
source
preuve
sortie candidate
version de travail
livrable valide
decision preparee
decision validee
sensible
a conserver
a supprimer
memoire candidate
memoire canonique
archive
```

Questions de Cerbere :

```text
Qu'est-ce qui doit disparaitre ?
Qu'est-ce qui doit rester marque comme candidat ?
Qu'est-ce qui est valide ?
Qu'est-ce qui engage ?
Qu'est-ce qui est sensible ?
Qu'est-ce qui peut etre reutilise ?
Qu'est-ce qui ne doit pas revenir ?
Qu'est-ce qui devient memoire candidate ?
Qu'est-ce qui peut devenir memoire canonique ?
Qui autorise ce retour ?
```

Dans une logique Pantheon :

```text
trace != memoire
memoire candidate != memoire canonique
sortie candidate != livrable valide
archive != preuve
usage ponctuel != droit de demeure
conservation != validation
suppression != oubli sans trace lorsque la responsabilite exige audit
retour != reutilisation legitime sans statut
```

## 15. Exemple concret

### Memoire projet

Prompt faible :

```text
Garde tout ca pour la suite.
```

Risque : le systeme conserve des hypotheses, brouillons, preferences ponctuelles ou erreurs corrigees comme contexte durable.

Prompt Cerbere :

```text
Ne garde rien automatiquement.
Classe les elements en :
1. ephemere ;
2. brouillon ;
3. hypothese ;
4. a verifier ;
5. valide ;
6. sensible ;
7. memoire candidate ;
8. a supprimer.

Pour chaque memoire candidate, indique :
- pourquoi elle devrait revenir ;
- dans quel perimetre ;
- avec quelle duree ;
- sous quel statut ;
- quelle autorisation est necessaire.
```

### Fin de dossier

Prompt faible :

```text
Archive le dossier.
```

Prompt Cerbere :

```text
Avant archivage, distingue :
1. livrables valides ;
2. sources ;
3. preuves ;
4. brouillons a ne pas reutiliser ;
5. hypotheses abandonnees ;
6. decisions preparees mais non validees ;
7. traces sensibles ;
8. elements a supprimer ;
9. memoires candidates ;
10. memoires canoniques possibles.

Ne laisse revenir plus tard que les elements valides ou explicitement marques comme candidats.
```

## 17. Cartel explicatif

```text
CERBERE — Garder les seuils du retour

Cerbere garde l'entree des Enfers. Il ne garde pas un tresor indistinct : il garde un seuil entre les mondes. Hercule le maitrise, le montre, puis Cerbere retourne a sa place.

Avec l'IA, cette epreuve concerne ce qui reste apres le travail : prompts, sources, brouillons, versions, hypotheses, sorties candidates, preuves, logs, decisions, memoires, archives et donnees sensibles.

Le danger n'est pas seulement de perdre une information. Le danger est aussi de garder trop, de garder mal, ou de laisser revenir ce qui n'avait pas ete valide.

Garde-fou :
classer chaque trace selon son statut : ephemere, brouillon, hypothese, candidat, a verifier, valide, sensible, a conserver, a supprimer, memoire candidate, memoire canonique, archive.

Phrase a retenir :
Une memoire mal gardee fait revenir ce qui aurait du rester mort.
```

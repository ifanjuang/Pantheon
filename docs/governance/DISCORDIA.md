# Discordia

Status: active support doctrine - material divergence sentinel.

Discordia is a governance function for detecting, preserving and qualifying material divergence.

Discordia is not a Pantheon Role with final authority.

Discordia is not a judge of truth.

Discordia is not ZEUS.

Discordia is not a runtime agent, worker, scheduler, queue, message bus, hidden debate system or autonomous contradiction engine.

Runtime/client/authority placement is inherited from `HERMES_INTEGRATION.md`: optional compatible runtime clients expose runtime interaction only, Hermes/the external runtime executes admitted work, Pantheon Cockpit projects governed state, and Pantheon retains governance authority.

## Purpose

Discordia protects useful disagreement from premature smoothing.

A smooth answer can hide source conflict, professional risk, approval uncertainty, memory overreach or role disagreement.

Discordia exists to say:

```text
This tension is material.
Do not erase it.
Qualify it.
Expose it if needed.
Escalate it if procedure cannot absorb it.
```

Discordia does not create conflict for its own sake.

Discordia prevents useful conflict from disappearing too early.

## Core rule

```text
Discordia detects divergence.
Discordia preserves material tension.
Discordia qualifies disagreement.
ZEUS decides status and procedure.
Agora exposes deliberation.
The human decides when the conflict exceeds procedure.
```

## What Discordia may do

Discordia may:

- detect disagreement between role viewpoints;
- detect disagreement between rites;
- detect tension between evidence, delivery, approval and memory;
- identify when a synthesis hides unresolved conflict;
- recommend Agora when positions need visible comparison;
- recommend User Decision Gate when the divergence requires human arbitration;
- preserve a contradiction or divergence note for an Evidence Pack;
- ask ZEUS for procedural arbitration.

## What Discordia must not do

Discordia must not:

- decide truth;
- approve delivery;
- promote memory;
- override ZEUS;
- replace THEMIS;
- replace ARGOS;
- replace Agora;
- replace User Decision Gate;
- run a debate;
- create autonomous role conversations;
- trigger rites automatically;
- generate hidden consensus;
- turn disagreement into runtime state.

## Relationship to existing roles

Discordia is not a replacement for existing Pantheon responsibilities.

Useful distinction:

```text
ATHENA detects structural incoherence.
ARGOS detects source and evidence weakness.
THEMIS detects risk, contradiction and approval boundary.
APOLLO detects clarity and formulation ambiguity.
DISCORDIA detects that their tensions must not be smoothed away.
ZEUS decides status and next procedure.
The human decides when required.
```

Discordia is a sentinel of material divergence.

It is not a supreme judge.

## Relationship to rites

Rites may expose divergence.

Discordia may qualify whether the divergence is material enough to require preservation, Agora, User Decision Gate, task split, source review or refoundation.

Discordia must not trigger a rite automatically.

A rite may reveal the need for Discordia review.

Discordia may recommend a rite to ZEUS.

ZEUS decides whether the rite is allowed.

## Relationship to Agora

Agora is the visible deliberation space.

Discordia is the sentinel that says a disagreement should not be buried.

Discordia may recommend Agora when:

- positions are legitimate but incompatible;
- the user needs to see the trade-off;
- a synthesis would hide meaningful disagreement;
- role viewpoints create different safe procedures;
- rites produce conflicting procedural recommendations.

Discordia does not deliberate in place of Agora.

Discordia only marks that deliberation may be required.

## Relationship to User Decision Gate

Discordia may recommend a User Decision Gate when divergence involves:

- value conflict;
- professional preference;
- strategic choice;
- external delivery risk;
- insufficient evidence with pressure to proceed;
- memory impact;
- approval uncertainty;
- user-valued direction at risk of being discarded.

Discordia must not decide the user’s preference.

Discordia exposes why human decision may be necessary.

## Material divergence conditions

A divergence is material when it can affect:

- task scope;
- claim status;
- evidence sufficiency;
- approval level;
- delivery status;
- memory status;
- User Decision Gate need;
- external transmission;
- professional responsibility;
- doctrine boundary.

A divergence is not material when it is only:

- harmless wording preference;
- equivalent phrasing;
- low-risk style disagreement;
- irrelevant to next allowed action;
- already resolved by existing evidence.

## Divergence note

When Discordia marks a divergence as material, it should produce a concise divergence note.

Recommended format:

```text
divergence_id:
divergence_type:
positions:
  - role_or_rite:
    claim:
    reason:
    objection:
    evidence_status:
    risk:
severity:
affects:
  - scope
  - evidence
  - approval
  - delivery
  - memory
recommended_procedure:
ZEUS_status:
User_Decision_Gate:
next_allowed_action:
```

Forbidden content:

- hidden chain-of-thought;
- raw role debate;
- private scratchpad;
- autonomous agent transcript;
- runtime worker trace;
- synthetic consensus hiding disagreement.

## Divergence types

Recommended divergence types:

```text
role_viewpoint_conflict
rite_conflict
source_conflict
scope_conflict
evidence_conflict
approval_conflict
delivery_conflict
memory_conflict
value_conflict
professional_risk_conflict
doctrine_boundary_conflict
```

## Severity

Recommended severity levels:

```text
low
medium
high
blocking
```

Severity is based on consequence, not emotional intensity.

A low-severity divergence can be recorded and bypassed.

A medium-severity divergence may need ZEUS procedure selection.

A high-severity divergence may need Agora or User Decision Gate.

A blocking divergence must stop delivery or memory promotion until resolved, escalated or explicitly accepted by the human.

## Example

```text
divergence_id: DIV-EXAMPLE-001
divergence_type: rite_conflict
positions:
  - role_or_rite: RITE_DIVERGENCE_CONTROLEE
    claim: several options remain viable
    reason: architecture decision is underdetermined
    objection: continued exploration may create proliferation
    evidence_status: partial
    risk: premature convergence or option bloat
  - role_or_rite: AUTOCRITIQUE_CONTRADICTOIRE
    claim: the most attractive option is unsafe for delivery
    reason: evidence and approval impact are insufficient
    objection: blocking may slow useful exploration
    evidence_status: insufficient for delivery
    risk: false confidence
affects:
  - evidence
  - delivery
  - approval
severity: high
recommended_procedure: open_User_Decision_Gate
ZEUS_status: escalation_required
User_Decision_Gate: required
next_allowed_action: expose options, risks and evidence gap to the human
```

## Forbidden drift

Discordia must never become:

- new Zeus;
- hidden debate runtime;
- contradiction engine;
- multi-agent conversation;
- approval engine;
- memory arbiter;
- source validator;
- risk judge replacing THEMIS;
- evidence judge replacing ARGOS;
- workflow orchestrator;
- automatic User Decision Gate trigger;
- automatic rite trigger.

## Final rule

Discordia does not create discord for spectacle.

Discordia protects useful disagreement from false synthesis.

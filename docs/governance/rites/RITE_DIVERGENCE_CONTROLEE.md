# Rite de Divergence Controlee

Status: active doctrine - shared rite.

## Intention

Widen the option space before convergence while preventing early critique from contaminating generation.

This rite is a Pantheon adaptation of an external divergent-ideation pattern observed in `uditakhourii/adhd`.

Pantheon distills the method only.

It does not import the project, install a runtime, create a new Pantheon Role or approve an external dependency.

## Trigger conditions

Use this rite when:

- the problem is open-ended;
- several viable options may exist;
- the obvious answer may be too poor;
- architecture, naming, doctrine or strategy is uncertain;
- a seductive solution needs adversarial testing;
- ZEUS detects premature convergence;
- Agora exposes multiple positions but lacks a bounded method for comparison.

## Anti-triggers

Do not use this rite for:

- simple lookup;
- known root cause;
- low-risk wording correction;
- single-answer factual question;
- urgent task where delay creates more risk than value;
- tasks where source verification is the primary need and divergence would create noise.

## Roles called

- ZEUS triggers, bounds and closes the rite.
- ATHENA frames the problem and clusters options.
- APOLLO clarifies evaluation criteria.
- HEPHAISTOS produces candidate options.
- THEMIS critiques, scores and detects traps after generation.
- ARGOS checks source and evidence implications.
- IRIS prepares the visible synthesis and handoff.

Hermes may execute external fan-out only under Task Contract.

Pantheon does not run the fan-out.

## Procedure

1. ZEUS defines the allowed scope and expected output status.
2. ATHENA reformulates the problem.
3. APOLLO defines evaluation criteria.
4. HEPHAISTOS produces divergent options without critique.
5. THEMIS reviews after generation, not during generation.
6. ATHENA clusters options by underlying angle.
7. THEMIS marks traps, seductive failures and premature convergence.
8. HEPHAISTOS deepens the strongest survivors if authorized.
9. ARGOS records evidence needs, missing sources and unsupported claims.
10. ZEUS assigns status: draft, continue, narrow, escalate or block.
11. IRIS prepares the handoff for OpenWebUI, Agora, Hermes or the user.

## Outputs

- option clusters;
- shortlist;
- non-obvious defensible option;
- trap list;
- deepened options;
- evidence needs;
- ZEUS status;
- User Decision Gate if required.

## Evidence Pack impact

If this rite changes output legitimacy, the Evidence Pack should record:

- why the rite was triggered;
- options considered;
- rejected traps;
- criteria used;
- evidence needs;
- unresolved tensions;
- ZEUS status.

The Evidence Pack must not store hidden chain-of-thought or raw scratchpad.

## User Decision Gate impact

Open a User Decision Gate when:

- options imply different professional risk;
- values, priorities or strategic preference must be chosen by the human;
- evidence is insufficient to safely rank options;
- role statuses remain incompatible after critique;
- external delivery, memory promotion or doctrine change depends on the selection.

## Memory impact

The rite may produce a Register Candidate only when a reusable pattern is explicit, scoped and evidence-linked.

The rite must not promote a Registre Probatoire entry.

## Failure modes

- too many options without decision value;
- critique during generation, which collapses divergence too early;
- attractive but unsupported options;
- false consensus after clustering;
- treating shortlist as validation;
- bypassing User Decision Gate when human preference is required.

## Forbidden drift

This rite must not become:

- runtime fan-out;
- autonomous multi-agent debate;
- hidden workflow;
- scheduler;
- queue;
- tool dispatch plan;
- automatic decision engine;
- approval callback;
- memory promotion pipeline.

## Final rule

Generation is not approval.

Critique is not proof.

A shortlist is not validation.

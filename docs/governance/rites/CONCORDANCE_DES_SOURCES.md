# Concordance des Sources

Status: active doctrine - shared rite.

## Intention

Compare sources before allowing a claim to support a candidate output.

This rite preserves the distinction between retrieved knowledge, source reference, Evidence Item and Evidence Pack.

`ANSWER_VERIFICATION_GATE.md` currently remains a candidate / to-verify proposal. Its `V0`-`V4` answer postures and `K0`-`K4` consequence levels may inform review only as candidate vocabulary until separately promoted under the repository authority lifecycle. They do not bind this active rite and do not create a second source-verification owner.

The active ownership composition remains:

```text
ARGOS challenges source authority, provenance and support.
Concordance des Sources structures claim-to-source verification when a rite is warranted.
THEMIS preserves contradiction and risk.
MNEMOSYNE contributes continuity, version and supersession review when material.
ZEUS arbitrates status and next procedure.
Evidence Pack retains the reviewable proof package.
The human decides consequential effects.
```

If the candidate Answer Verification Gate is later promoted, it may compose with this rite as the answer-posture boundary. Until then, this rite relies on existing active source, Evidence, status and approval owners rather than importing candidate V/K levels as binding doctrine.

This composition does not make the rite mandatory for every source-backed claim. A single authoritative, applicable and sufficient source may satisfy the declared scope without invoking a rite. When source conflict, version uncertainty, freshness, provenance or overextended support is material, this rite is the canonical shared procedure rather than a parallel RAG or evidence-validation subsystem.

## Trigger conditions

Use this rite when:

- several sources may disagree;
- freshness matters;
- a claim supports delivery, approval or memory;
- source provenance is unclear;
- retrieved knowledge risks being mistaken for evidence;
- source-backed assertion is consequential and support is not already clear and sufficient;
- ARGOS or THEMIS reports a source gap;
- a professional output depends on a claim that could affect liability, transmission or memory.

## Anti-triggers

Do not use this rite when:

- no source-backed claim is being made;
- the output is explicitly speculative;
- the task is low-risk drafting with no evidence claim;
- a single authoritative source is already identified, applicable and sufficient for the declared scope.

## Roles called

- ARGOS maps sources, provenance and claim support.
- THEMIS identifies contradiction and risk.
- APOLLO clarifies what each source actually supports.
- ATHENA structures the claim-to-source relationship when needed.
- MNEMOSYNE contributes current-state, version and supersession review when continuity or remembered state is material; she does not replace source authority.
- ZEUS decides whether evidence is sufficient for the next status and whether another procedure or User Decision Gate is required.

## Procedure

1. List source references.
2. Identify date, version, scope, applicability and provenance.
3. Extract the claims each source supports.
4. Mark unsupported or overextended claims.
5. Detect contradictions.
6. Identify stronger and weaker support.
7. Assign freshness, limitation and confidence notes.
8. Decide whether the claim can support draft, delivery or memory candidate, or must remain blocked / to verify under existing active status owners.

## Outputs

- source matrix;
- claim-to-source map;
- contradiction ledger;
- freshness and applicability note;
- confidence level;
- Evidence Pack entry;
- ZEUS status.

## Evidence Pack impact

If the rite affects output legitimacy, the Evidence Pack should record:

- sources used;
- scope of each source;
- exact source identity and revision when available;
- claim supported by each source;
- contradiction status;
- freshness, applicability or version risk;
- unsupported claims;
- approval impact.

The Evidence Pack must not treat source quantity as proof.

## User Decision Gate impact

Open a User Decision Gate when:

- sources disagree on a decision-critical claim;
- applicability or currentness cannot be resolved for a consequential claim;
- the user must choose whether to continue with reserve or wait for stronger evidence;
- external delivery would rely on partial or stale evidence;
- memory promotion is proposed from insufficient or contradicted evidence.

## Memory impact

This rite may support a Register Candidate only if the claim is scoped, source-backed and linked to an Evidence Pack.

The rite must not promote a Registre Probatoire entry.

## Failure modes

- treating retrieval as validation;
- hiding source contradictions in a smooth synthesis;
- citing a source beyond what it supports;
- confusing freshness with authority;
- treating the newest version as automatically applicable;
- treating repeated sources as independent confirmation when they share origin;
- treating candidate Answer Verification Gate vocabulary as active binding doctrine before promotion.

## Forbidden drift

This rite must not become:

- retrieval runtime;
- ranking engine;
- citation authority engine;
- RAG validator;
- automatic evidence generator;
- currentness authority;
- permission engine;
- answer-posture authority;
- memory promotion pipeline.

## Final rule

Retrieval is not evidence.

Citation is not validation.

Latest is not automatically applicable.

Candidate doctrine is not binding doctrine.

Source volume is not proof.

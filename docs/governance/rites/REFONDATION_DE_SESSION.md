# Refondation de Session

Status: active doctrine - shared rite.

## Intention

Stop a polluted or overgrown session and restart from a clean Task Contract.

This rite protects the work from Hydre-like proliferation: every correction creates new ambiguity unless the frame is reset.

## Trigger conditions

Use this rite when:

- the session has too many contradictory iterations;
- context bloat reduces clarity;
- previous prompts contaminate the current decision;
- outputs keep improving locally but worsening globally;
- too many variants obscure the original objective;
- a user, role or ZEUS detects that continuation would preserve confusion;
- a new Task Contract would be safer than further patching.

## Anti-triggers

Do not use this rite when:

- a small revision is enough;
- evidence is stable and only wording needs work;
- the user explicitly needs continuity with the current trace;
- refoundation would discard unresolved evidence or approval history.

## Roles called

- ZEUS decides whether to refound.
- ATHENA extracts stable invariants and new structure.
- ARGOS preserves sources and evidence references.
- THEMIS preserves unresolved risks and approval constraints.
- APOLLO preserves quality criteria.
- IRIS prepares the clean handoff.

## Procedure

1. Identify why continuation is unsafe or inefficient.
2. Separate stable constraints from session noise.
3. Preserve validated sources, decisions and limitations.
4. Preserve unresolved risks and contradictions.
5. Mark discarded variants as historical context, not memory.
6. Create a new Task Contract draft.
7. Resume from the clean contract only after ZEUS status is explicit.

## Outputs

- refoundation note;
- preserved invariants;
- discarded noise;
- unresolved tensions;
- source preservation note;
- new Task Contract draft;
- ZEUS status.

## Operational template

`templates/context_handoff/SESSION_HANDOFF.md` provides a non-executable handoff template for this rite.

The template is support material only.
It does not create a new doctrine, runtime, memory cleanup flow, approval record or automatic Task Contract launcher.

Use it when the work needs a fresh context without losing the distinction between:

- validated decisions;
- candidate ideas;
- unresolved risks;
- source references;
- discarded session noise;
- next bounded action.

Core rule:

```text
A handoff preserves continuity.
It does not preserve authority.
```

## Evidence Pack impact

If this rite affects an output, the Evidence Pack should record:

- reason for refoundation;
- preserved sources;
- preserved decisions;
- discarded assumptions or variants;
- unresolved risks;
- new Task Contract reference.

The Evidence Pack must not treat the old session as a Registre Probatoire entry.

## User Decision Gate impact

Open a User Decision Gate when:

- refoundation would discard a user-valued direction;
- multiple reset strategies are valid;
- unresolved risk affects the new Task Contract;
- professional delivery, approval or memory depends on what is preserved.

## Memory impact

The old session may generate Register Candidates only for explicit, scoped, evidence-linked and approved reusable patterns.

The rite must not convert session history into a Registre Probatoire entry.

## Failure modes

- discarding useful evidence;
- hiding unresolved contradictions;
- treating reset as deletion;
- converting old session noise into memory;
- refounding too often and losing continuity.

## Forbidden drift

This rite must not become:

- automatic context pruning;
- hidden memory cleanup;
- runtime reset command;
- scheduler or queue reset;
- automatic Task Contract launcher;
- memory promotion or deletion pipeline.

## Final rule

When correction multiplies confusion, refound the frame.

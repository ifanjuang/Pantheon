# Pantheon Next Visual Language

Status: active doctrine — visual language, non-runtime metaphor.

This document defines the visual language of Pantheon Next.

It supports diagrams, illustrations, interface metaphors, presentation boards and narrative explanations.

It does not define implementation.

It does not introduce a runtime.

```text
Optional runtime clients may expose interaction.
Hermes Agent executes external admitted work.
Pantheon Cockpit projects governed Cards, decisions and status.
Pantheon Next governs.
The human decides consequential effects.
```

## Central image

Pantheon Next is represented as a governed antique city placed inside a world of possible knowledge, sources and actions.

The user is the player.

The city does not act alone.

The city makes decisions more readable, traceable and reliable.

## Central phrase

```text
L'IA ouvre les possibles.
Pantheon les organise.
L'humain décide.
Le validé reste.
```

This phrase should guide visual composition.

Visuals should show possibility, organization, decision and validated persistence.

## Main layers

Pantheon visuals should distinguish five layers.

```text
Outside world
Verification docks
Governed city
Underground workshops
Skies of possibility
```

These layers are metaphorical.

They are not runtime layers.

## Outside world

The outside world represents unverified possibility.

It may include:

- sea of sources;
- knowledge fields;
- archive ruins;
- data forests;
- dossier mountains;
- reference villages;
- roads and ports.

The outside world can feed a quest.

It must never be shown as a Registre Probatoire entry.

## Source boats

External sources may be shown as boats.

Recommended mappings:

| Source type | Visual image |
|---|---|
| Web page | Light boat |
| Social network | Noisy corsair |
| Open data | Fishing boat |
| SaaS platform | Merchant ship |
| Official source | State galley with seal |
| Doubtful source | Dark-water vessel |

No boat should enter the city directly.

Every source should pass through the verification docks.

## Verification docks

The docks represent source qualification.

They may show:

- provenance;
- reliability;
- status;
- contradiction;
- proof;
- seal;
- approval.

The docks are essential.

They visually prevent accidental canonization.

## Knowledge fields

Knowledge fields represent consultable material.

They may show:

- norms;
- guides;
- precedents;
- public corpora;
- domain references;
- feedback from practice;
- official documentation.

Knowledge nourishes quests.

Knowledge is not a Registre Probatoire entry.

This distinction should be visible.

## Governed city

The city represents governed continuity.

Recommended mappings:

| City element | Pantheon meaning |
|---|---|
| Central Pantheon | System doctrine and stable principles |
| Districts | Projects |
| Squares | Work sessions |
| Houses | Discussions, decisions, validated fragments, deliverables |
| Bridges | Controlled exchange |
| Gates | Approval boundaries |
| Walls | Scope and compartmentalization |
| Canals | Governed circulation |
| Porticos | Review and transition spaces |

The city should look ordered but alive.

It should not look like a machine that executes by itself.

## Cloisonnement

Compartmentalization must be visible.

Use walls, gates, canals, porticos, bridges and terraces to show that projects and governed records do not merge accidentally.

A project district should not silently leak into another project district.

A working session should not silently become system doctrine.

A source should not silently become a Registre Probatoire entry.

## Underground workshops

The underground workshops represent fabrication.

They may show:

- reports;
- diagrams;
- images;
- exports;
- tools;
- skills;
- deliverables;
- patch candidates.

They are the forge of outputs.

They must remain visually subordinate to governance.

Do not represent the underground as Pantheon owning execution.

Fabrication remains bounded by Task Contracts, Evidence Packs and approvals.

## Skies of possibility

The skies represent AI possibilities and oracle-like capabilities.

They may show:

- fast reasoning;
- deep analysis;
- vision;
- writing;
- search;
- domain expertise;
- alternative futures.

Oracles illuminate.

They do not govern.

The sky should suggest possibility without implying that models decide truth.

## Companions

Companions represent governed viewpoints and role perspectives.

Recommended first-reading set:

| Companion | Function |
|---|---|
| Athena | Structures |
| Argos | Qualifies sources and evidence |
| Themis | Guards limits and risk |
| Apollo | Clarifies and checks readiness |
| Hephaistos | Prepares fabrication |
| Iris | Prepares transmission |
| Zeus | Arbitrates status and procedure |
| Mnemosyne | Preserves continuity and frames memory reuse |

Companions should not be shown as autonomous workers inside Pantheon.

They accompany the quest.

They produce candidate perspectives.

They do not self-promote truth, evidence or memory.

## Hermes and Iris

Use Iris for narrative transmission inside the visual metaphor.

Hermes Agent is already the external runtime in the technical doctrine.

Using Hermes as a visual messenger inside the city can blur the doctrine.

If Hermes appears visually, he should represent the external execution bridge, not an internal Pantheon role that governs the Registre or doctrine.

## Mnemosyne

Mnemosyne is the canonical continuity and memory-governance figure.

She may be shown near archives, project chronology, revision stacks, bridges between prior and current states, or the threshold before durable retention.

Her visual responsibilities may include:

- identifying the relevant memory domain or project history;
- orienting a bounded search by exact term, semantic proximity, chronology or declared relation;
- exposing index, date, version, duplication and supersession;
- distinguishing historical material from the currently reusable state;
- proposing session, Project, Agency, Sandbox, archive or Register Candidate placement.

She must not be depicted as:

- an autonomous memory agent;
- a vector database or memory provider;
- a search executor;
- a truth oracle;
- an automatic archivist that rewrites history;
- an automatic Registre promotion mechanism.

The external memory product also named `Mnemosyne` is a separate candidate technology identity and should never be represented by the Pantheon Role figure without an explicit product label.

## Visual anti-patterns

Avoid visuals that suggest:

- Pantheon acts alone;
- the city is an execution engine;
- companions are autonomous workers;
- the Registre updates itself;
- Mnemosyne promotes memory automatically;
- sources enter the Registre directly;
- knowledge fields are Registre Probatoire entries;
- oracles govern truth;
- workshops are runtime ownership;
- approvals trigger automatic action;
- project boundaries are decorative only.

## Preferred composition

A clear Pantheon visual should show:

1. an outside source or intention;
2. a verification threshold;
3. a governed city boundary;
4. a human decision point;
5. an Evidence Pack or review trace;
6. a Register Candidate;
7. possibly a Registre Probatoire entry after approval.

## Final rule

The visual language may be rich, mythological and game-like.

The doctrine must remain sober:

Pantheon does not execute.

Pantheon governs what can be trusted, approved and remembered.
